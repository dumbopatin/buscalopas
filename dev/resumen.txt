TRABAJAR / VERIFICAR (regla del proyecto)
--------------------------------------------------------------------------------
- Local: `bash dev/jugar.sh` (levanta server.js en :3000 y abre el navegador) o
  `cd dev && npm start`. Para ver en el MÓVIL de la misma WiFi: http://<IP-PC>:3000/
  (jugar.sh imprime la IP). NO abrir index.html con doble clic (file:// → CORS rompe fetch).
- Vista móvil desde el PC: `cd dev && bash preview-mobile.sh` (Chromium 390x844 táctil).
- Tras tocar lógica/UI: `cd dev && npm run test-lopa`  (Playwright, 48 checks).
- Tras tocar economía/dificultad: `cd dev && npm run balance`.
- Verificación sintaxis tras cada cambio: `node --check game.js` (raíz) y
  `node --check server.js`, `node --check test-lopa.js`, `node --check balance-check.js` (dev/).
- La versión vive en config.js: `window.APP_VERSION` (ahora '2.3'). Solo se toca ahí.

ARQUITECTURA DE DATOS (DOBLE BACKEND)
--------------------------------------------------------------------------------
- config.js tiene SUPABASE_URL + anon key → el cliente usa Supabase (tabla scores
  con stats como JSONB; además friendships, friend_requests, chat_messages, notes).
- Sin Supabase (local/tests) → fallback a dev/server.js (scores.json) o localStorage.
- PRODUCCIÓN = Netlify + Supabase SOLO (no hay server.js). Amigos/chat/notas/ranking
  usan Supabase. Si Supabase falla, cae a localStorage (sin amigos ni ranking).
- initSupabase(): probe HEAD a `/rest/v1/scores?select=name&limit=1` con apikey
  (2s timeout). Si no responde, supabaseClient=null → todo local. NO usar la raíz
  del dominio (404 sin CORS → rompía el deploy).
- Realtime (badges chat/solicitudes en vivo): requiere el bloque "TIEMPO REAL" de
  dev/supabase.sql (publicación supabase_realtime + replica identity full).
  Sin él funciona el polling de respaldo (~10s).
- Las notas y stats son POR USUARIO en Supabase (username PK).

USUARIO DEIDAD "LUCIFER" (pruebas)
--------------------------------------------------------------------------------
- Entrar con usuario "Lucifer" / contraseña "lucifer". NO es un jugador normal:
  isDeity(name) (case-insensitive) le da cartera 1.000.000 (DEITY_WALLET), todos
  los LopAmuletos owned+active, 3 cargas, niveles 5, tienda abierta (applyDeityBoost).
  loadRanking/searchUsers lo filtran (oculto). userExists devuelve false (no
  agregable). No se puede registrar otro "Lucifer" (confirmPassword lo bloquea).
- Broadcast: en su chat tiene "📢 Avisos de Lucifer" (BROADCAST_KEY '__avisos_lucifer__')
  para enviar mensajes a todos (chat_messages con user_to=ese marker; local usa
  /api/chat/broadcast). Los demás ven "😈 Lucifer" (chat 1-a-1) al principio de su lista.
- OJO tests: los de broadcast escriben en dev/chat.json (canal de pruebas, tope 200).

MECÁNICA DEL JUEGO (estado actual)
--------------------------------------------------------------------------------
- Tamaños 9/14/18 (9 por defecto; 14 y 18 se compran en tienda). Dificultad:
  "0.06-180" Fácil, "0.10-120" Media, "0.14-60" Difícil (claves en select + textos.js).
- 3 modos pero SOLO "classic" está desbloqueado (turulos/hybrid salen 🔒 disabled;
  lockUnavailableModes). Los tests los habilitan con evaluate.
- Elementos: minas "papela", celda "spiz" (+20% tiempo, +40% en Lucifer, bonus al
  final si no se gasta), turulos = banderas (clic derecho).
- Modo LUCIFER: entra al quedar ≤20% del tiempo. Turulos valen ×2·(1+0.5·nivel)
  (luciferTuruloMultiplier). Nivel comprable en tienda (luciferUpgrade, máx 5).
- Dinero al ganar: timeRemaining × mult (x1/x5/x20) × 0.1 + bonus amuletos/mejoras,
  + turulos correctos (+1/+2/+3) + spiz guardado (escala: 20/60/120). Al perder SOLO turulos.
- ESTADÍSTICAS (statsData, persistidas vía saveStats): { games, wins, losses,
  bestEarning, spizSaved, timePlayed, luciferReached, luciferTime, turulosWins,
  correctTurulos, ipod, ipodTrack, musicTime, ipodNotified, lopa:{...}, by{} }.
  - lopa = { shopUnlocked, owned{}, active{}, charges{milagro,ultimobaile,vidente},
    levels{spiz,dinero,lucifer}, uses{subidon,dragon}, order[], relicGames, acquired{} }.
  - by{} = partidas por "dificultad_tamaño" → {g,w,l}.
  - OJO: las ganancias usan gameCorrectTurulos (de LA PARTIDA), no el total de por vida.

LOPAMULETOS / TIENDA (estado actual)
--------------------------------------------------------------------------------
- TIENDA = Dragon Narco de Ojos Azules. Stock diario con PRNG por fecha (3 objetos
  daily: milagro, ultimobaile, spizUpgrade, dineroUpgrade) + essentials siempre
  (board14, board18, chami) + reliquias (syntek 400€, nword 300€, charlie 250€ —
  requieren iPod, visibles pero bloqueadas sin él). Regala la Carta del Dragón la 1ª vez.
- AMULETOS (textos.js + buildAmulet, placeholders {VIDENTE_RECHARGE_EVERY}...):
  positivos: rizao, subidon, iman, vidente, papu, rastreador.
  de carga (CHARGE_AMULETS): milagro, ultimobaile. negativos permanentes: mala, sombra, gafe.
  RELIC: dragon (Carta del Dragón, botón +50€ cada 10 partidas), syntek (inmunidad 3s
  si suena "Duele el Amor" y está activa), nword (da "Hypnotize"), charlie (da la canción).
- VIDENTE = de cargas (1/partida, recarga +1 cada 5 victorias desde que se obtuvo,
  máx 3). Sin carga no revela el Spiz.
- HUD: los amuletos se ordenan por lopa.order (orden de adquisición). Los upgrades
  (level-spiz, level-dinero, level-lucifer, reveal-lvl) también entran en order.
- IMPORTANTE: ALL_AMULETS se construye con Object.assign({}, ..., {dragon: RELIC_DRAGON})
  (si se pasa RELIC_DRAGON directo rompe renderHudAmulets).
- MÓVIL: fila con scroll horizontal + botón "▾" (#hud-amulets-all) que abre el panel
  con TODOS los LopAmuletos (ver/activar/desactivar, clic → visor). El visor
  (#amulet-modal) tiene el toggle de activar/desactivar (positivos pasivos).
