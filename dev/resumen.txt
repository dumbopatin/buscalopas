TRABAJAR / VERIFICAR (regla del proyecto)
--------------------------------------------------------------------------------
- Local: `bash dev/jugar.sh` (levanta server.js en :3000 y abre el navegador) o
  `cd dev && npm start`. Para ver en el MÓVIL de la misma WiFi: http://<IP-PC>:3000/
  (jugar.sh imprime la IP). NO abrir index.html con doble clic (file:// → CORS rompe fetch).
- Vista móvil desde el PC: `cd dev && bash preview-mobile.sh` (Chromium 390x844 táctil).
- Tras tocar lógica/UI: `cd dev && npm run test-lopa`  (Playwright, 48 checks).
- Tras tocar economía/dificultad: `cd dev && npm run balance`.
- Verificación sintaxis tras cada cambio: `node --check game.js` (raíz) y
  `node --check server.js`, `node --check test-lopa.js`, `node --check balance-check.js` (dev/).
- La versión vive en config.js: `window.APP_VERSION` (ahora '2.5'). Solo se toca ahí.

--------------------------------------------------------------------------------
ARQUITECTURA DE DATOS (DOBLE BACKEND)
--------------------------------------------------------------------------------
- config.js tiene SUPABASE_URL + anon key → el cliente usa Supabase (tabla scores
  con stats como JSONB; además friendships, friend_requests, chat_messages, notes).
- Sin Supabase (local/tests) → fallback a dev/server.js (scores.json) o localStorage.
- PRODUCCIÓN = Netlify + Supabase SOLO (no hay server.js). Amigos/chat/notas/ranking
  usan Supabase. Si Supabase falla, cae a localStorage (sin amigos ni ranking).
- initSupabase(): probe HEAD a `/rest/v1/scores?select=name&limit=1` con apikey
  (2s timeout). Si no responde, supabaseClient=null → todo local. NO usar la raíz
  del dominio (404 sin CORS → rompía el deploy).
- Realtime (badges chat/solicitudes en vivo): requiere el bloque "TIEMPO REAL" de
  dev/supabase.sql (publicación supabase_realtime + replica identity full).
  Sin él funciona el polling de respaldo (~10s).
- Las notas y stats son POR USUARIO en Supabase (username PK).
- SUGERENCIAS (buzón compartido): tabla `suggestions` (id, username, note, created_at),
  política abierta como el resto. Cualquier jugador INSERTA; Lucifer (el jefe) ve
  la lista en el modal de Sugerencias. Local: dev/suggestions.json + /api/suggestions.
  El traspaso de notas entre usuarios se ELIMINÓ (las sugerencias no son personales).
