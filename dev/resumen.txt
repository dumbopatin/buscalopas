================================================================================
BUSCALOPAS — RESUMEN DE CONTEXTO (sintetizado, última actualización 24/08)
================================================================================
Juego tipo buscaminas "Cyber-Lopera" (móvil + desktop). Repo git desde 21/08.
Histórico detallado antiguo: dev/resumen-historico-2026-08-20.txt (solo si se
necesita cómo se hizo algo antiguo). APP_VERSION en config.js (ahora '2.7').

REGLAS DE TRABAJO (importantes):
- GIT: el usuario decide cuándo commitear/pushear. NO hacer git add/commit/push
  salvo que lo pida explícitamente (ej. "sube los cambios"). Remote:
  github.com/dumbopatin/buscalopas (rama master). Comando: `git add -A &&
  git commit -m "..." && git push`.
- RESUMEN: NO tocar resumen.txt salvo que lo pida (como git).
- No commitear: dev/, server.js, dev/scores.json|chat.json|friends.json|
  notes.json|suggestions.json, logs, node_modules (en .gitignore).

ESTRUCTURA / QUÉ SE SUBE A NETLIFY
- RAÍZ = sitio estático que SÍ se sube: index.html, style.css, game.js,
  config.js, textos.js, pwsave.html (NO quitar), vendor/ (supabase.min.js),
  img/ (incl img/amulets/), audio/.
- dev/ = NO se sube: server.js, tests, scripts, resumen*.txt, logs, scores.json.

TRABAJAR / VERIFICAR
- Local: `bash dev/jugar.sh` (server.js en :3000 + navegador; imprime IP y
  túnel Cloudflare con QR). Móvil en la misma WiFi: http://<IP-PC>:3000/.
- Vista móvil desde PC: `cd dev && bash preview-mobile.sh` (Chromium 390x844).
- Tests: `cd dev && npm run test-lopa` (Playwright, 48 checks). Balance:
  `npm run balance`. Sintaxis: `node --check game.js` (y server.js, tests).
- Tras tocar UI/lógica: npm run test-lopa + comprobar 390x844.

ARQUITECTURA DE DATOS (DOBLE BACKEND)
- Producción = Netlify + Supabase SOLO (tablas: scores, friendships,
  friend_requests, chat_messages, notes, suggestions). Sin Supabase → fallback
  a dev/server.js (scores.json) o localStorage. initSupabase(): probe HEAD a
  `/rest/v1/scores?select=name&limit=1` con apikey (2s timeout); si no
  responde supabaseClient=null → todo local. Realtime (badges en vivo) requiere
  el bloque "TIEMPO REAL" de dev/supabase.sql. SUGERENCIAS = buzón compartido
  (tabla `suggestions`); Lucifer ve la lista, el resto escribe.
- Al cargar partida se FUSIONA la config local (fijados/activos/orden/mejoras/
  cargas/canción iPod/ipodNotified) sobre los datos del servidor y se re-sube
  (mergeConfigIntoServer en loadStats): evita perder config si la última subida
  no llegó al refrescar. Los contadores (partidas/récords) vienen del servidor.

MECÁNICA DEL JUEGO
- Tamaños 9/14/18 (9 por defecto; 14 y 18 en tienda). Dificultad: "0.06-180"
  Fácil, "0.10-120" Media, "0.14-60" Difícil. 3 modos pero SOLO "classic"
  desbloqueado (turulos/hybrid 🔒; tests los habilitan con evaluate).
- Minas "papela", celda "spiz" (+20% tiempo, bonus si no se gasta), turulos =
  banderas (clic derecho; en móvil pulsación larga).
- Modo LUCIFER al quedar ≤20% del tiempo: turulos valen ×2·(1+0.5·nivel).
- Dinero al ganar: timeRemaining × mult × 0.1 + bonus amuletos/mejoras +
  turulos correctos (+1/+2/+3) + spiz guardado (escala 20/60/120). Al perder
  solo turulos. statsData persistido vía saveStats (localStorage + Supabase/
  /api). OJO: ganancias usan gameCorrectTurulos (de LA PARTIDA).
- Subidón = amuleto con CARGAS (máx 1; SUBIDON_RECHARGE_EVERY=3, recarga cada
  3 victorias al ganar; al entrar en Lucifer gasta 1 carga → +10s). Antes era
  "1 vez por partida" sin cargas.
- Syntek = reliquia con botón de inmunidad (3s) SOLO si suena "Duele el Amor"
  y está activa; AHORA se usa UNA vez por partida (syntekUsedThisGame) y el
  botón desaparece al usarla. Botones de reliquias: Syntek SIEMPRE encima del
  dragón (dragón debajo), ambos aparecen en partida y desaparecen al usarse.

LOPAMULETOS / TIENDA / iPOD
- TIENDA = Dragon Narco de Ojos Azules. Stock diario con PRNG por fecha
  (3 objetos daily: milagro, ultimobaile, spizUpgrade, dineroUpgrade) +
  essentials (board14, board18, chami) + reliquias (syntek 400€, nword 300€,
  charlie 250€ — requieren iPod). Regala la Carta del Dragón la 1ª vez.
- Amuletos positivos: rizao, subidon, iman, vidente, papu, rastreador. De
  carga: milagro, ultimobaile (CHARGE_AMULETS), vidente y subidon (cargas en
  statsData.lopa.charges). Negativos: mala, sombra, gafe. RELIC: dragon,
  syntek, nword, charlie. ALL_AMULETS se construye con Object.assign (no pasar
  RELIC_DRAGON directo, rompe renderHudAmulets).
- iPOD (nano 3 negro, fijo sobre el fondo, se compra 666€): música de fondo.
  IPOD_TRACKS: cyber, luciferbeats, spizamarillo, nhh/cousins, dueleamor
  (Syntek), biggie (N Word), charlie. Móvil: botón "—" minimiza a shuffle
  (clip + ⏮▶⏸⏭). Al comprar un objeto que desbloquea canción, el toast de
  "canción nueva" sale EN SECUENCIA tras el "Comprado" (checkIpodTrackUnlocks
  con delay 1600ms y toasts encadenados a 2600ms; la marca ipodNotified se
  guarda al momento para que no vuelva a salir al refrescar).
- HUD: amuletos por lopa.order. Móvil: fila con scroll + botón ▾
  (#hud-amulets-all) que abre el panel con TODOS (ver/activar/desactivar,
  Fijar/Quitar máx 4 en la barra — MAX_PINNED=4, lopa.pinned).
